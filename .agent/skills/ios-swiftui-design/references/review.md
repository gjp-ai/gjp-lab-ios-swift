# SwiftUI review guide

Review the requested code without editing unless changes are also requested.

- Trace each screen from its navigation entry and state owner through effects and callbacks.
- Inspect semantic colors, accessibility labels, reachable states, safe areas, Dynamic Type, previews/tests, and supported window sizes.
- Report only actionable findings, ordered by impact. Include the code path, user consequence, triggering condition, and smallest safe remediation.
- Do not require a view model, coordinator, custom design system, or adaptive dependency solely because it is common elsewhere.
- If no material issue remains, say so and note unverified paths.
